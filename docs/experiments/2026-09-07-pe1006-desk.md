# A desk of real agents on one hard problem

**Date:** 2026-09-07
**Status:** Recorded — the harness works, the problem is not closed
**Code:** `crates/tinyhivemind/examples/desk`
**Compared against:** a Grok Bot desk that answered the same problem on
2026-09-05, recovered from that client's local store

## What this asks

The deliberation benchmark asks whether a protocol beats a poll on a synthetic
room with a right answer. The crosstalk harness asks whether a message one
agent writes reaches the peer it names. Neither asks the question a host asks
before it ships anything:

> Seat real models on a desk, give them a problem that takes hours and code,
> and does the thing hold?

Project Euler 1006 is that problem. Ψ(k) is the sum of squares of the decimal
values of the k+1 distinct length-k factors of the Fibonacci word; the desk
must produce Ψ(10¹⁸) mod 101001001. Two samples are published — Ψ(3) = 20302
and Ψ(10) ≡ 10699667 — and the answer is not. Brute force reaches k ≈ 10³.

## The two rooms

Both rooms ran four seats on one shared transcript, with the same division of
labour, because the seats here were written from the Grok desk's own roster
rather than designed to win.

| | Grok Bot desk | this desk |
| --- | --- | --- |
| seats | Theory, Solver, Checker, Johnny (coordinator) | theory, solver, checker, lead |
| model | one frontier model, every seat | `deepseek-v4-pro`, every seat, pinned |
| a message starts | as many turns as it names | exactly one turn |
| a seat between turns | one long-lived session | a fresh process, resumed by session id |
| coordination | an agent in the room | a chair outside it, on a cadence |
| storage | the client's own | a JSONL log behind `SessionLog` |
| memory | none visible | CortexDB, recalled per turn |
| **result** | **62418970, in 79.6 minutes** | **structure closed, residue not computed** |

The Grok desk's 17 room messages sat on top of roughly 110 messages of private
per-agent working sessions — the desk was a coordination layer over four agents
that were each already running. That is the difference the table above is
really recording, and it is worth being precise about it rather than reading
the wall-clock column as a model comparison.

## What one message, one turn costs and buys

`mention_dispatch` returns `MentionDispatchDecision::One` or nothing; there is
no variant carrying two. So a reply naming four seats starts one turn, and a
desk cannot quietly spawn N processes. That is the rule the library exists to
enforce and it held for every one of the 28 turns here.

It also has two costs this run paid, and both are host problems rather than
library ones:

**A pair can monopolise a room.** Theory and Solver kept naming each other, so
the chain never died, so the chair — which only spoke when the room fell
silent — never got a word in. Over sixteen turns, two of four seats never
spoke once. The fix is a chair that speaks on a cadence and alternates between
the seat holding unfinished work and a seat that has never spoken. The first
time it fired, Checker did the first independent recompute anybody had done,
caught the binary-vs-decimal trap, and told Solver that the recurrence it had
spent six turns asking for was already in the files. The desk's own loop was
broken by the seat the mechanism had been starving.

**A chain dies on a message that names nobody.** Four times a seat ran out of
time mid-task and its landed message named no peer, so `NoDirectAgentMention`
ended the chain — correctly — and the chair's round-robin then handed the turn
to a seat that had not been doing the work. Nudging the last speaker instead
recovers the thread.

## What the room actually did

Every claim below was checked against an independent brute-force oracle
written outside the desk, and every one of them held:

- the k+1 factors are `f[i:i+k]` for `i ∈ [0, F_m-1] ∪ [F_{m+1}-1-(k-F_m), F_{m+1}-1]` — exact for k = 3..59;
- consecutive sorted factor values differ by `9·10^e`, each `e ∈ [0, k-2]` exactly once, plus a single `+1` — exact for k = 3..39;
- the exponent permutation is the rotation by 1/φ², a three-gap Christoffel staircase, and the general-n order follows from a Fibonacci fold plus an insertion rule;
- Ψ reduces to seven aggregates over that rotation, and `psi_assembly` reproduces the sliding-window ground truth for k = 3..200, hitting 20302, 10699667 and 50567341;
- `rank_β(n, i) = S(n) - S(n-i) + S(i+1) - n·⌊iβ⌋ + i` with `⌊iβ⌋ = (isqrt(5i²)-i)//2`, exact integer, O(log n), correct at 10¹⁸.

The room corrected itself three times without being asked: Solver killed
Theory's "order-40 recurrence" as Berlekamp-Massey overfitting, Theory
disproved Solver's `s_r` claim with a proof about `F_{q-1}² ≡ (-1)^q`, and
Checker found that the two files named `psi_fast` and `psi_blockwise` were
placeholders that computed nothing.

What it did not do is aggregate `Σ_i rank(i)·g^i` in closed form — the last
step, and the same wall the Grok desk hit, where it was cleared by the
`S = U(M) + Corr` rewrite.

## Five things a host owes, found by running it

1. **A killed turn has said nothing.** One turn cost 90k tokens across 27 tool
   calls and posted nothing at all. The library cannot know a process was
   killed; the host owes the room a message.
2. **Asking a model not to use tools does not work.** Told in as many words to
   run nothing and just summarise, the CLI ran eight more commands and hit the
   deadline again. The wrap-up had to move to a plain completion, where there
   is no tool to call.
3. **`max_tokens` is spent on reasoning first.** That wrap-up then came back
   empty with `finish_reason: length` at 1200, and again at 8000 — the whole
   budget went to reasoning tokens on both DeepSeek tiers. Uncapped, the same
   call answers in 350 tokens. A silent seat looked like a refusal and was a
   cap set too low.
4. **Setting the child's working directory does not move its writes.** An
   agent CLI resolves a write against its own project root, found by walking
   up for a `.git`. The seats wrote into the repository checkout, and an
   auto-commit hook filed four of their scratch files into the branch before
   anybody noticed. `--dir` fixes it; check where the first file lands.
5. **An upstream failure reads as silence.** A turn ran its full budget and
   printed one `error` event: OpenRouter, reached as a fallback while Surplus
   was erroring, refused with a 402. Nothing distinguished that from a model
   that would not speak until the host read the event stream and kept stderr.

## The ladder

Neither `reasoning` nor `max-reasoning` ever seats `deepseek-v4-pro`. Both rank
rungs by admitted price divided by multiplier, so the first answers on
`deepseek-v4-flash` and the second on `glm-5.2` — legitimately, and invisibly
unless the caller reads `x-ladder-model`. A run that has to say which model
produced a result needs a ladder whose every rung is that model; `deepseek` and
`deepseek-flash` in this box's config are that, and a flash rung added to
either would win on price and silently turn it back into `flash`.

## Cost

28 turns, 3.3M tokens reported, 459 router calls, about ten hours of wall
clock against the Grok desk's eighty minutes. Most of that gap is the
one-process-per-turn seat boundary: a seat re-reads the room and the workspace
every turn, and a resumed CLI session only partly repairs it.

## What would close it

The remaining step is bookkeeping, not mathematics. `rank_β` is a sum of a few
terms; a rank-weighted power sum is the sum of the weighted sums of those
terms, and each is geometric or a Beatty power sum with the Euclidean
recursion the desk already uses for `S`. The desk has been told this is the
shape of the step and not what the step is.

## Runs 26 and 27

The `O(log n)` claim in the section above was false when it was written, and
the desk is what found that out. `@checker` measured the `B↔C` recursion at
depth ~1.23n, calls ~0.62n, and refused to sign off — correctly. Everything
below is what happened after that refusal.

**The room lost the answer to a fence.** `@solver` cleared the blocker on its
next turn with a Fibonacci self-similarity of `floor_β` drawn from the periodic
continued fraction `β = [0;1,1,1,…]`, verified against brute force, reaching
`B(g,10^18)` in 27 calls. It closed the message with `<<<POST>>> … <<<POST>>>`
rather than `<<<POST … POST>>>`, and `extract_post` took the last marker as an
opener: the transcript row the room received was the three characters `>>>`.
The room read that as silence and the chair nudged a seat that had just spoken.
The extractor now accepts both fences.

**The workspace saved what the transcript dropped.** The result was not lost,
because the same turn had written `psi_sublinear.py` and a NOTES.md section
before posting, and the chair's nudge says to read NOTES.md. Stigmergy carried
what messaging failed to. That is an argument for the shared workspace being
load-bearing rather than a convenience, and it was an accident.

**Restarts flood the window.** Each restart appends the task again, and by run
26 five identical copies of it occupied half of every seat's ten-row window —
two thirds of a 13k-character prompt was duplicated stale instruction. A fresh
transcript and an 865-byte brief cut the prompt to 4.9k.

**The timeout is one budget and it was tuned three times in an hour, twice
wrongly.** Raising the router's `request_timeout` to 600s reverted a documented
finding that 600s overshoots, and the stated reason for raising it — that a
turn's context had outgrown the cap — was contradicted by the raw stream: the
call that exhausted the ladder carried 48k of context and produced 374 output
tokens. What the stream did show was reasoning tokens jumping from ~40 to
29,234 in the step before the hang, and a hard probe put to the same model
returned nothing in 864s. Both numbers are in the config and `STALL_AFTER`
comments now, because the next person to widen either will reach for the same
wrong reason.

**Neither safety fired.** In the final turn the child outlived both the 900s
stall threshold and the 2400s turn deadline, reaching 44 minutes with the
host's main thread verifiably inside its own poll loop. Killing the child
externally produced `silent after 1157.29s` — a quiet timer that had already
passed the threshold it was checked against. The cause is not established. The
host prints nothing about its own deadline, quiet timer, or buffer length,
which is why four separate diagnoses of this subsystem tonight were inferred
from the outside and three of them were wrong. Instrumenting those three
numbers is the next change, before any further tuning.

## What is verified

Independently, against brutes written without reference to the desk's code:

- `B(x,n)` matches at 160 `(x, n)` pairs up to n≈6000, past the n≤610 the desk
  tested, including a base it never tried.
- `C`, `T`, `R` match at 60 pairs up to n=1200, past the desk's n≤200.
- `S` is exact at m = 317, 1000, 4001, and `S(10^18)/10^36 = 0.3090169943749474`
  against β/2 = 0.30901699437494745 — fourteen digits on a value no brute force
  reaches.
- `B(g,10^18) = 79414112` and `R(g,10^18) = 91481916`, both in milliseconds.

`Ψ(10^18) mod 101001001` remains uncomputed. `PrefG`, `P1w`, `PrefF` and
`Tail1` are still brute-forced, and the assembly on top of them is unwritten.
